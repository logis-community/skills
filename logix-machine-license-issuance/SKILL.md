# Logix 单机离线证书签发

使用 Keygen 为 Logix 设备生成机器绑定的 `.lic`，并按确认结果维护原台账。以下是本 Skill 指定的默认值：目标部署先查找本机 Docker 中的 Keygen；产品为 `logix`；策略为一年订阅；许可证有效期为一年。策略名称及其续订语义与许可证 `expiry` 是不同字段，分别读取、设置和验证，不能用策略的 `duration` 代替许可证有效期。单机一证是既有约束，不是批量参数。

这些默认值只适用于本次任务，不能从历史记录补全接收人或其他参数。用户明确指定的本次值优先。只读发现和预览可以先进行；创建或修改 Keygen 资源、激活 machine、checkout 证书、回写台账及向外发送文件都会产生实际变更，必须先取得本次明确确认。Skill 调用本身、过去的确认、默认值、沉默或旧记录都不构成签发授权。

## 签发前

1. 读取工作簿全部相关工作表，确认签发对象/接收人、设备标识、发放标记及期限字段含义。新签只处理明确未发放且字段完整的行；重签须明确对应的已发放行及旧记录。64 位小写十六进制设备指纹必须来自 Logix 客户端。遇到多个候选工作簿、模糊状态、重复指纹、同名文件或相互冲突的期限，先核实，不猜测；不得从其他用户、批次或历史记录推断本次接收人或参数。
2. 只读发现 Keygen 部署。默认先检查本机 Docker 部署并核对实例身份；发现多个实例、没有本机 Docker 实例或不能确认目标实例时，列出可辨认的信息并询问用户，不猜测，也不连接其他环境。未确认唯一目标实例前停止。读取当前实例实际账户、产品、策略和 entitlement 数据；默认产品 `logix`、策略为实际数据确认的一年订阅策略（当前名称“订阅版 · 1 年”仅作查找线索，不凭名称猜测）。核对目标 policy 属于该产品且 `maxMachines` 符合单机约束。读取 policy 的 `duration`、许可证的 `expiry` 及 checkout 文件 `meta.expiry` 时分别记录；按实际系统模型分别设置并验证一年策略与一年有效期。若目标实例中找不到唯一匹配的默认产品或策略，先列出可读名称和必要属性并澄清。
3. 对本次尚未明确的参数逐项询问并记录答复：接收人/许可证 `name`；是否关联 entitlement；是否添加 metadata 及每个键、值和值类型；本次批量是否使用统一配置，还是逐证书定制。策略和有效期默认一年，用户可指定其他期限。entitlement 默认不自动关联；用户确认关联后，查询并关联所有能够从实际 Keygen 数据准确判定为 Logix 相关的 entitlement。若无法准确判定“所有 Logix 相关”，先列出可读名称、code/资源 ID 和关联依据供用户澄清。metadata 和批量模式等未提供且没有指定默认值的信息必须询问；明确的“无”也要作为本次答复记录。必要字段未齐或答复不明确时，不进入签发。
4. 只读检查设备指纹对应的 machine、父 license 和现存证书，完整遍历分页，核对是否可复用并避免重复创建。若已有对象或文件状态模糊，先查清楚。按本次参数准备完整签发预览，写明：目标 Keygen 实例、对象/接收人及数量、产品、entitlement 选择和实际集合、策略及其续订语义、许可证期限与文件期限、metadata、批量统一或逐证书定制、重复项处理，以及计划进行的 Keygen 变更、台账回写和文件交付。**紧贴最终预览取得用户对本次签发及所列变更的明确确认后，才执行任何 Keygen 写请求**（包括创建、修改、关联授权、激活与 checkout）。若确认后任一关键参数、对象、数量、目标实例或变更范围发生变化，先更新预览并重新确认。CE 1.7.2 的可用字段、限制和核对方法见 [Keygen 机器文件细节](references/keygen-machine-file.md)。
5. 为本次运行保留私有的行号到许可证、机器、文件及已确认条款的映射；不要把密钥、令牌、指纹、证书内容或个人信息写入普通日志、仓库或结果正文。请求超时或结果不明时，先查询服务端状态，避免重发创建请求。

## 逐行签发

1. 只有本次预览及其变更已明确确认、且授权条款均已确认的行才能继续。复用现有记录前，按 policy 继承项加 license 专属项的**完整有效 entitlement 集合**、`metadata` 和其他已确认的可选条款逐项比对；确认“无”时，entitlement 有效集合与 metadata 必须为空，其他可选项不得有 license 专属覆盖。连同**接收人/用户名、策略、产品、许可证期限、文件期限和设备绑定**全部相符，且现存文件内也是相同快照时才复用。缺少、多出或值不同都不能复用旧文件；新签或重签前按确认结果创建替代 license，不擅自改动旧记录或共享 policy。新 license 的 `name` 为已确认的接收人，policy 为已核对的目标策略；按已确认的值设置可选属性，并在 checkout 前关联已确认的 license 专属 entitlements。创建后回读实际 `expiry` 及所有授权条款，并分别验证策略 `duration`、许可证期限和证书文件期限符合预览。
2. 用该 license 为设备指纹激活 machine，再从 machine checkout 未加密的 `MACHINE FILE`，请求中包含 `encrypt: false` 和 `include: ["license", "license.entitlements"]`；即使确认“无 entitlements”也显式请求并验证空集合。一年文件的 Keygen CE 1.7.2 参数与时间陷阱见 [Keygen 机器文件细节](references/keygen-machine-file.md)；始终以签出文件的实际日期验证期限。
3. 使用当前账户公钥验 Ed25519 签名，并核对文件类型、指纹、机器与父许可证 ID、用户名、policy、产品、`ACTIVE` 状态、单机额度、父许可证及文件各自的到期日；再核对签名内父 license 的 `metadata`、可选属性及 `included` 中 entitlement 的完整集合、code 和相关值与确认结果完全一致，无缺项或额外项。若文件未包含可复验的已确认字段，停止交付并查明原因。有效截止时间是两种到期日中较早者。把证书写入私有目录后再从磁盘读取并复验。文件名按任务要求使用 `<用户名>离线证书.lic`；同名冲突时用稳定行号或设备标识摘要区分并记录映射。
4. **只有该行证书创建、导出、复验成功后**，才把该行标记为已发放。保留工作簿其他值、公式、格式与对象；不要因导出工具重写样式而交付改变范围扩大的文件。失败或模糊的行保持原标记。校验最终工作簿及每份文件，并按用户指定的受控渠道交付；报告成功、失败、跳过数量与原因，不在正文粘贴许可证或个人信息。

## 重签或改策略

重签也须重新展示并逐项确认授权条款，不能沿用旧文件的 entitlements、metadata 或其他可选值作为用户本次决定。现有 license 的 policy 可能不允许直接改绑。先创建符合新策略、用户名及全部已确认授权条款的替代 license、machine 与证书，并完成上述验证；之后再停用旧 license。保留旧记录以便追溯，不在结果不明时反复创建。**停用服务端许可证无法即时撤销已经分发的离线签名文件**；明确指出旧文件被新文件替代，已分发副本也需要更换。

具体 Keygen 请求、期限核对和文件结构见 [references/keygen-machine-file.md](references/keygen-machine-file.md)。
