# Logix 单机离线证书签发

使用 Keygen 为已收集设备标识的用户生成机器绑定的 `.lic`，并维护原台账。默认按当前 Logix 的“订阅版 · 1 年”策略、单机一证处理；用户明确指定其他条款时，以该条款为准。签发和修改台账是实际写操作，先确认当前任务已有授权；不要因为使用了本 Skill 就自行发证或修改策略。

## 签发前

1. 读取工作簿全部相关工作表，确认姓名或用户名、设备标识、发放标记及表内期限字段的含义。新签只处理明确未发放且字段完整的行；重签须明确对应的已发放行及旧记录。64 位小写十六进制设备指纹必须来自 Logix 客户端。遇到多个候选工作簿、模糊状态、重复指纹、同名文件或相互冲突的期限，先核实，不猜测。
2. 从当前部署配置和 Keygen 查询账户、Logix 产品、目标 policy 及其 `maxMachines`、`duration`、继承的 entitlements；核对用户名应写入许可证 `name`，目标 policy 确实属于 Logix 且只允许一台机器。若要求“父许可证无到期日”同时又要求有限期订阅 policy，先澄清最终条款。
3. **在任何新签或重签的 Keygen 写请求（包括创建、修改、关联授权、激活与 checkout）之前**，向用户展示每行或同条款批次的待签发摘要：用户名、设备、产品、policy、单机额度、父证书与文件期限，以及 policy 已继承的授权。逐项询问是否附带额外 `entitlements`（确认每个 code/资源 ID）、许可证 `metadata`（每个键、值及类型）和其他实际支持的可选授权条款（如额度覆盖、owner/group；逐项确认具体值或明确“无”）。把答复记为“已确认：具体值/无”或“未确认”；默认值、台账空白和沉默都不等于“无”。回答不明确、要求的授权与 policy 继承内容冲突、或部署/客户端不支持所需字段时，先澄清并停止该行写操作。CE 1.7.2 的可用字段、限制和核对方法见 [Keygen 机器文件细节](references/keygen-machine-file.md)。
4. 按设备指纹查询已有 machine、父 license 和现存证书，检查完整分页。文件存在或创建请求结果不明时，先核对服务端状态，避免重复签发。为本次运行保留私有的行号到许可证、机器、文件及已确认授权条款的映射；不要把密钥、指纹、证书内容或个人信息写入普通日志、仓库或结果正文。

## 逐行签发

1. 只有授权条款均已确认的行才能继续。复用现有记录前，按 policy 继承项加 license 专属项的**完整有效 entitlement 集合**、`metadata` 和其他已确认的可选条款逐项比对；确认“无”时，entitlement 有效集合与 metadata 必须为空，其他可选项不得有 license 专属覆盖。连同**用户名、策略、产品、期限和设备绑定**全部相符，且现存文件内也是相同快照时才复用。缺少、多出或值不同都不能复用旧文件；新签或重签前按确认结果创建替代 license，不擅自改动旧记录或共享 policy。新 license 的 `name` 为台账用户名，policy 为已核对的目标策略；按已确认的值设置可选属性，并在 checkout 前关联已确认的 license 专属 entitlements。创建后回读实际 `expiry` 及所有授权条款。
2. 用该 license 为设备指纹激活 machine，再从 machine checkout 未加密的 `MACHINE FILE`，请求中包含 `encrypt: false` 和 `include: ["license", "license.entitlements"]`；即使确认“无 entitlements”也显式请求并验证空集合。一年文件的 Keygen CE 1.7.2 参数与时间陷阱见 [Keygen 机器文件细节](references/keygen-machine-file.md)；始终以签出文件的实际日期验证期限。
3. 使用当前账户公钥验 Ed25519 签名，并核对文件类型、指纹、机器与父许可证 ID、用户名、policy、产品、`ACTIVE` 状态、单机额度、父许可证及文件各自的到期日；再核对签名内父 license 的 `metadata`、可选属性及 `included` 中 entitlement 的完整集合、code 和相关值与确认结果完全一致，无缺项或额外项。若文件未包含可复验的已确认字段，停止交付并查明原因。有效截止时间是两种到期日中较早者。把证书写入私有目录后再从磁盘读取并复验。文件名按任务要求使用 `<用户名>离线证书.lic`；同名冲突时用稳定行号或设备标识摘要区分并记录映射。
4. **只有该行证书创建、导出、复验成功后**，才把该行标记为已发放。保留工作簿其他值、公式、格式与对象；不要因导出工具重写样式而交付改变范围扩大的文件。失败或模糊的行保持原标记。校验最终工作簿及每份文件，并按用户指定的受控渠道交付；报告成功、失败、跳过数量与原因，不在正文粘贴许可证或个人信息。

## 重签或改策略

重签也须重新展示并逐项确认授权条款，不能沿用旧文件的 entitlements、metadata 或其他可选值作为用户本次决定。现有 license 的 policy 可能不允许直接改绑。先创建符合新策略、用户名及全部已确认授权条款的替代 license、machine 与证书，并完成上述验证；之后再停用旧 license。保留旧记录以便追溯，不在结果不明时反复创建。**停用服务端许可证无法即时撤销已经分发的离线签名文件**；明确指出旧文件被新文件替代，已分发副本也需要更换。

具体 Keygen 请求、期限核对和文件结构见 [references/keygen-machine-file.md](references/keygen-machine-file.md)。
