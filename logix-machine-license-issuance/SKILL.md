# Logix 单机离线证书签发

为 Logix 设备生成机器绑定的 `.lic`，并按确认结果维护原台账。先完成发现、核对和预览，再签发；每条记录独立处理和验收。

## 默认值与边界

- 目标部署默认先找本机 Docker 中的 Keygen；产品默认 `logix`；策略默认一年订阅；许可证有效期和 MACHINE FILE 有效期默认各一年。`policy.duration`、许可证 `expiry` 和文件 `meta.expiry` 属于不同字段，分别核对和设置。
- 本次明确指示优先于默认值。不得从其他用户、批次、历史证书或旧确认推断本次对象、授权或期限。表格数据只用于识别本次待办记录，不代替用户对未指定条款的答复。
- 只读发现和预览不产生签发变更。创建/修改许可证、关联 entitlement、激活 machine、checkout、回写台账和向外发送文件都需在本次预览后得到明确确认。参数、对象、数量、目标实例或变更范围变化时，先更新预览并重新确认。
- 如果本机 Docker 实例不存在、实例不唯一、无法确认实例身份，或目标实例的凭据/权限不可用，停止并说明具体阻碍；不得猜测或改连其他环境，也不得在访问受阻时依据旧记录声称已完成查询。

## 签发流程

### 1. 核对记录与部署

- 从本次指定的工作簿/智能表格读取相关工作表和实时记录。确认接收人/用户名、机器标识、发放标记及字段含义。新签只处理明确未发放且资料完整的记录；重签须明确对应记录和旧证书。设备指纹须来自 Logix 客户端，并核对为 64 位小写十六进制。
- 发现多个候选表格、状态不明、重复指纹、同名对象或期限冲突时，先澄清。不要仅凭姓名、文件名或用户类型匹配已有许可证。
- 在确认的本机 Docker Keygen 中只读核对账户、产品、policy、entitlements 及其关联。使用实际资源 ID；核对产品关系、`maxMachines` 和 policy 的 `duration`。`“订阅版 · 1 年”`只作查找线索，不能代替实际数据验证。不能唯一识别默认产品或策略时，列出可读名称和关键属性请用户确认。

### 2. 收齐本次参数

先核对机器、父 license 和现存证书，遍历完整分页，判断是否可复用及是否需要重签。然后补齐没有明确答案的事项：

- 接收人及许可证 `name`；通常以本次记录中的用户名作为 `name`，但若台账字段或接收对象不明确，要询问。
- 是否添加 license 专属 entitlements。默认不新增关联；用户确认关联时，按实际 Keygen 数据找出所有可确认属于 Logix 的项。无法准确判定“所有 Logix 相关”时，列出名称、`code`/资源 ID 和归属依据，请用户澄清。单独说明 policy 已继承的 entitlement；`include` 只控制导出内容，不会授予权限。
- 是否添加 `metadata`，以及每个键、值和值类型；其他实际支持的可选授权属性也逐项确认具体值或明确“无”。未给答案不能当作“无”。
- 本批次使用统一配置，还是逐证书定制。逐证书定制时，为每条记录收齐自己的值。
- 策略和许可证期限；默认一年订阅和一年 license 有效期。文件期限默认一年，并与 license 期限分开核对。
- 若请求向外发送证书，确认具体接收人和渠道；签发前核实该渠道可用且接收对象匹配。渠道不可用时先问替代方案，不得自行改发给其他人或会话。

必需值未齐、授权范围不清或用户答复含糊时，暂停相关记录。不要为满足“所有 entitlement”而默默创建账户级资源、修改共享 policy 或改变共享 entitlement 的 metadata。

### 3. 展示预览并确认

完成只读检查后，在任何写请求之前一次性展示最终预览，至少包括：

- 目标 Keygen 实例，以及对象/接收人和数量；
- 产品、policy 及其续订/时长语义、policy 继承的 entitlement；
- license 专属 entitlement 的确认结果和实际集合；
- license `expiry` 与 MACHINE FILE 有效期/预计截止日；
- metadata 及已确认的其他可选属性；
- 批量统一或逐证书方式、重复项处理；
- 计划进行的 Keygen 变更、台账回写和文件交付渠道。

等待用户对本次预览及所列变更的明确确认。确认后、开始写入前重新读取实时待发记录和相关 Keygen 状态；若它们与预览不同，停止并重新预览确认。

### 4. 逐条签发与防重复

- 只有确认范围内的完整记录才能执行。复用现有 license/machine/file 前，比较接收人、产品、policy、license 和文件期限、机器绑定、完整有效 entitlement 集合、metadata 及其他已确认属性；还须确认磁盘证书的签名快照完全相同。缺项、多项或值不同均不能复用旧证书。
- 新签按确认值创建 license。改变旧 license 的名称、policy、期限或其他条款时，不直接改旧记录或共享 policy；按确认范围创建替代 license、machine 和文件。对已确认补授权的既有 license，先读取完整有效 entitlement 集合，只关联确实缺少的项；policy 继承项不重复添加。关联后回读核对，再 checkout。不要为解决单纯的导出参数遗漏而另建 license 或 machine。
- checkout 使用未加密 MACHINE FILE，并显式包含 `license`、`license.product`、`license.policy` 和 `license.entitlements`。检查响应确实包含全部请求路径；缺失任何路径或授权条目时暂停交付。具体请求和格式见 [Keygen 机器文件细节](references/keygen-machine-file.md)。
- 对超时、断连或结果不明的写请求，先查询 Keygen 是否已创建或关联，再决定下一步；不得盲目重发造成重复资源。

### 5. 验证、回写与交付

- 将文件写入私有目录，再从磁盘读取验证 Ed25519 签名、文件类型、指纹、machine/父 license ID、用户名、产品、policy、`ACTIVE` 状态、单机限制、到期时间，以及已确认的 metadata/属性和完整 entitlement 集合。有效截止时间取 license 与文件期限中较早者。文件名使用 `<用户名>离线证书.lic`；同名时用稳定行号或设备标识摘要区分，并私下记录对应关系。验收细节见引用文档。
- 每条证书独立通过验证后，才回写该条发放标记；保留表格其他值、公式、格式和对象，并回读确认实际值。界面或 API 的只读标记不能代替实际写入结果；若写入被拒绝，如实报告，不能标称台账已更新。
- 只向预览中确认的渠道和接收人交付，核对发送结果。发送失败时不要擅自换收件人或会话；报告阻碍并按用户确认的替代方案继续。证书正文不粘贴密钥、令牌、设备指纹、个人信息或完整证书内容。
- 为本次运行保留私有的记录到 license、machine、文件及已确认条款映射。不要把管理员密码、令牌、license key、设备指纹、证书内容或个人信息写入普通日志、仓库或结果正文。汇报成功、失败、跳过数量及原因；批量任务部分失败时按行汇总，不把部分成功表述为全部成功。

## 重签、补授权与替换

重签或改变用户、policy、期限、entitlements、metadata 等条款，必须重新预览并获得本次确认；不能把旧文件中的授权当作用户新决定。若仅是旧 checkout 漏含 `license.*` 关系，而服务端 license/machine 已符合确认条款，修正 include 后从现有 machine 重新 checkout 并复验，避免重复创建资源。若服务端 license 本身缺少用户确认的 entitlement，则先补齐缺项、回读，再 checkout。其他 license 条款需要变更时，先创建并验证替代 license、machine 和文件，再停用旧 license；不要在新文件验证成功前停用旧 license。

任何服务端变更都不会改写已分发的离线签名文件。替代文件通过验证后再停用旧 license，并明确通知接收方更换旧文件；停用服务端许可证不能即时撤销旧离线文件。保留旧记录以便追溯。
