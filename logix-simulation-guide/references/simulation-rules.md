# 建模与数据规则

## 逻辑与场景

以客户端 4.1.4-15 的领域规则为准。建模规则用于检查案例意图和引用关系。工作台保存会汇总并定位必填属性缺失、货架巷道连接问题或悬空路径等警告，允许案例先保存。运行前按下表核对所需条件。[源码定位](#来源)

| 条件 | 规则与核对动作 |
| --- | --- |
| 流程需要创建新货物或承接外部任务 | 起点用「发生器」创建新货物，或用「进入」承接已有任务、订单或事件。沿连线从起点追到终点，终点按业务语义用「退出」或「吸收器」，其中「吸收器」会销毁货物。 |
| 货物只在场景内部移动 | 只表达内部移动，省去「发生器」与「吸收器」。自动搭建时用 `internalChains` 标明内部移动流程的端点。 |
| 在场景画布布置设备和路径 | 按 1 px = 1 cm 换算尺寸和间距。例如 2 m 的布局间距在画布上对应 200 px。 |
| 外部流程需要连接 AGV 网格 | 用「电子拣选货架」做出入口，通过货架属性关联内部虚拟点。「作业点」需绑定两处节点引用，例如外侧作业点和网格内部 AGV 到达点。外部连线接到电子拣选货架，网格内虚拟点由货架属性引用。 |
| 场景使用货架 | 在逻辑画布配置「货架组」，核对实际引用的货架。 |
| 配置「货架组」「资源池」等孤立组件 | 在属性中配置引用关系，检查组件没有入边或出边。 |

## 案例包导入

4.1.4-15 在「案例库」使用同一个「导入案例」入口，按 ZIP 内是否含 `simulation_data.json` 识别旧包。[源码定位](#来源)

| 包格式 | 文件规则与导入后核对 |
| --- | --- |
| v1 旧包 | 有 `simulation_data.json` 时，系统先预览再尝试兼容转换，也会读取包内的 `.xlsx`（如有）。留意导入完成时的转换警告，打开案例核对场景、逻辑流程和关联数据集。转换场景失败时可能只留下空画布，Excel 缺失或读取失败时可能缺少订单、储位或规格数据。 |
| v2 案例包 | ZIP 根目录须有 `meta.json`、`scene.json`、`logic.json`，顶层均为 JSON 对象。`chains.json` 和 `dataset.json` 可选，顶层分别为数组和对象。`dataset.json` 中的订单、储位、规格和货架引用还需通过字段校验。提示缺少必需文件时检查 ZIP 是否多包了一层目录。 |

## 储位与导入

对 4.1.4-14 和 4.1.4-15，首次点「同步货架储位」前，先确认案例关联的目标数据集。目标已有储位时，清除三张表的勾选，以「导出数据集」备份完整 Excel。打开文件核对「储位表」包含待保留的货架编号、储位编码和库存等业务值，再同步。[源码定位](#来源)

| 条件 | 规则与核对动作 |
| --- | --- |
| 4.1.4-14 导入含储位的 Excel | 关联目标数据集并完成上述备份检查后，在工作台「数据集」中「同步货架储位」，再导入已有储位的业务数据。[4.1.4-14 发布说明](https://ipa-changelog.vercel.app/a/logix/v-4-1-4-14) |
| 4.1.4-15 从 Excel 新建数据集 | 可从一个文件创建货架组、货架、储位，并导入订单和规格。同名新建会分配独立名称。校验失败时按提示的工作表和原始行号修正文件，再检查导入结果和案例绑定。[4.1.4-15 发布说明](https://ipa-changelog.vercel.app/a/logix/v-4-1-4-15) |
| 向已有数据集合并或覆盖 Excel | 确认目标数据集和工作表。已有储位按货架编号和储位编码匹配，合并和覆盖都可能更新已有储位的业务字段，结构仍来自画布同步。找不到储位或归属有歧义时，先备份目标数据，再核对画布和同步结果，最后导入对应业务值。[源码定位](#来源) |
| 报错「画布包含重复储位编码，请先调整货架结构」 | 同一个货架编号下有重复储位编码。同步请求在写入储位结构前被拒绝。修正画布上的货架编号、储位编码或归属，确认组合唯一后再同步。[源码定位](#来源) |
| 警告「已移除存在歧义的 … 个货架和 … 个储位」 | 目标数据集已有重复货架编号或同一货架下的重复储位编码。警告出现时，系统已从目标数据集移除受影响范围，本次同步跳过重建。按提示中的货架编号核对画布，必要时修正后再次同步重建结构，再从同步前的备份或源表恢复业务值并核对。[源码定位](#来源) |

仅看到同步按钮旁的「存在重复储位身份，请先确认货架归属」时，先分别检查画布和目标数据集的货架编号与储位编码。这条待同步提示可能来自任一侧。[源码定位](#来源)
